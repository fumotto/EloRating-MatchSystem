# Changelog

本プロジェクトの主要な変更履歴を記録する。

この文書は、ユーザーおよび開発者が各バージョンで何が変更されたかを把握するためのものである。

設計判断は **DecisionLog.md**、詳細な変更履歴は **Git履歴** を参照すること。

本書は **Keep a Changelog** の考え方を参考に運用する。

---

# バージョン管理方針

本プロジェクトは Semantic Versioning（SemVer）を採用する。

```
MAJOR.MINOR.PATCH
```

* **MAJOR**：互換性のない変更
* **MINOR**：後方互換性のある機能追加
* **PATCH**：後方互換性のある不具合修正

---

# 更新ルール

以下の場合、本書を更新する。

* 新機能を追加した場合
* 既存機能を変更した場合
* 不具合を修正した場合
* セキュリティ修正を行った場合
* 廃止・削除を行った場合

軽微なリファクタリングやコメント修正など、利用者への影響がない変更は記載しない。

---

# 変更区分

## [1.1.0] - 2026-09-01

勝敗確定の再設計（ADR-032〜035）から、サブアカウント対策・管理者による対戦カードの作成
（ADR-036〜039）までをまとめて公開した。Migration 0023〜0025 を適用している。

**★本リリースは `reject-match` を削除している。** 本書の定義では互換性のない変更に当たるが、
Edge Functions はフロントエンドと同時に配置される内部APIであり、外部の利用者を持たないため
MINOR とした。**フォークして旧APIを呼んでいる場合は壊れる。**

### Added

**勝敗確定の再設計（ADR-032）**

* 投了（`concede-match`）。敗者が自チームの敗北を申告する。**これを基本の経路とした**
* 反対申告。勝利申告の押し間違えを「正しい側が申告し直し、誤った側が投了する」で解決する
* 報告期限の延長（`extend-match-deadline`）。長い対戦は当事者の宣言で扱う
* クールダウン（`teams.queue_cooldown_until`）。誤魔化す経路の代償を**レートではなく時間**で払わせる
* 信頼度の公開。不戦数・確定率・不成立数をチームごとに表示する

**通報と措置（ADR-033）**

* 通報（`create-abuse-report` / `withdraw-abuse-report` / `admin-resolve-abuse-report`）
* 通報は勝敗フローから独立し、レートにも試合の状態にも影響しない
* 措置はクールダウンとBANに限る。**確定した結果は訂正しない**

**外部要因による不成立と障害対応（ADR-034）**

* 対戦不成立の申請と応答（`request-no-contest` / `respond-no-contest`）
* ペアの再マッチ抑止（`match_avoidance`）。回線相性で対戦できないペアを一定期間外す
* 管理者による試合の無効化（`admin-void-matches`）
* 保守による一時停止（`maintenance_paused`）。シーズンの停止とは別に管理する

**サブアカウント対策（ADR-036）**

* ペア再戦の抑止。確定した試合の相手とは一定時間マッチしない
* ランキング掲載の最低対戦相手数。異なる相手と対戦するまで一覧に出さない
* 対戦の偏りの可視化（管理画面）。繰り返し当たっている組み合わせと稼ぎ先の集中を示す

**IPアドレス・端末情報は収集しない。** VPNや回線の使い分けで回避される一方、CGNATや共有回線
では無関係な他人を巻き込むためである。対策はすべて対戦の履歴だけを材料にしている。

**管理者による対戦カードの作成（ADR-035 ⑤ / ADR-039）**

* `admin-create-match`。大会・イベント向けに対戦する2チームを直接指定する
* レート差・再マッチ抑止・クールダウンには拘束されず、1チームへ複数割り当てられる

### Changed

* 同時参加の規則を「進行中の試合を持つチームは待機列に登録できない」と定義し直した（ADR-035）
* 承認期限の初期値を 10分 から 60分 へ（ADR-032 ⑨）。短いほど、遅い報告が奇襲として機能する
* システム設定画面を意味のまとまりで区切り、保守停止を専用トグルにした（ADR-037）
* マッチング画面が進行中の試合を一覧で示すようにした。複数持ちうるためである（ADR-039 ⑧）
* シーズン確定時に打ち切られた試合を「シーズンの終了により打ち切られました」と区別して表示する

### Fixed

* **シーズンが確定できない不具合**（ADR-038 ①）。`finalize-season` が `no_contest_reason` を
  設定せず引き分けを書いていたため、猶予切れの時点で進行中の試合が残ると制約違反で失敗していた
* ADR-032〜034 が追加した設定10列がAPIにも画面にも配線されておらず、運営が変更できなかった
  （ADR-037 ①）。**障害時手順の手順1である保守停止を立てられない状態だった**
* 保守停止中もマッチング画面が案内を出さず、押してから `QUEUE-007` で弾かれていた（ADR-038 ③）
* シーズン画面が保守停止中も「マッチング：受付中」と表示していた（ADR-038 ③）
* エラーコードの文言が欠けており、`QUEUE-006` / `QUEUE-007` / `MATCH-009`〜`012` /
  `ABUSE-001`〜`007` がすべて「予期しないエラーが発生しました」になっていた

### Removed

* 申告内容の拒否（`reject-match`）と `max_reject_count`（ADR-032 ②③）。
  **無料・無記録・単独で試合を消せる経路であったため**。`MATCH-007` は欠番とし、再利用しない
* 部分ユニークインデックス `ux_matches_active_team_a` / `_b`（ADR-035 ③）。
  意図した不変条件を保証しておらず、機能追加を偶発的に阻んでいた

### Security

* 疑わしいペアとチームの偏りを管理者にのみ公開する（ADR-036 ④）。基表は認証済みなら
  誰でも読めるため、View 自身に管理者の述語を置いて閉じた
* サブアカウント対策で個人を同定しうる情報を収集しない方針を確定した（ADR-036 ⑥）

## [1.0.0] - 2026-08-18

MVPを公開し、公開後の修正と機能追加を反映した最初のタグ付きリリースである。

**★MVPの公開そのものは 2026-08-10 だが、その時点では通しで動かなかった。**
PKCE・CORS・接続方式などクラウド固有の条件で表面化した不具合があり、実利用できる状態に
なったのは 2026-08-16 である。壊れた状態を 1.0.0 として残さないため、**タグは現在の状態へ付けた。**

### Added

**MVP（M1〜M5 / スライス S0〜S6）**

* Discord認証、プロフィール自動作成（`ensure-profile`）
* チーム作成、招待コードによるメンバー招集、脱退、リーダー移譲
* レート差によるマッチング、待機列、`matchmaker` による自動成立
* 勝利申告・承認・拒否、期限切れの自動解決（ADR-014）
* Eloレーティングの更新と `rating_history` への記録
* ランキング（未認証でも閲覧可・ADR-018）、試合一覧・試合詳細
* 管理機能（チームBAN／解除、システム設定、監査ログ・ADR-017）
* Realtime による画面同期、ダークモード

**公開後の追加**

* トップページとルールページ（Issue #8）
* 運営からのお知らせをヘッダーに表示（Issue #7）
* マッチング成立の演出とブラウザ通知（Issue #5）
* 試合確定時のレート変動表示（Issue #6）
* シーズンリセットとシーズン別ランキング（Issue #9 / ADR-030）
* 他チームのメンバー確認（ランキング・試合画面からの導線）
* メンバー一覧へのアイコン表示
* 稼働監視と Discord への通知（ADR-029）
* 選手向け・運営向けマニュアルの同梱
* MITライセンス

### Changed

* チーム人数上限の下限を2から1へ（Issue #4）
* BAN中のチームは編成を変更できないようにした（脱退・リーダー移譲も塞ぐ）
* マニュアルへの導線を設定画面からトップページへ移した
* DB接続を Connection Pooler 経由へ変更（ADR-028）
* CI を PR でのみ実行する運用へ変更し、`main` をブランチ保護した

### Fixed

* Discordログイン後にリダイレクトが解決しない問題（PKCEフロー・BASE_URL）
* すべての更新操作が CORS プリフライトで弾かれる問題
* ログアウト後にヘッダーの表示が切り替わらない問題
* セッション確定前にルータを作り直し、保護ルートが `/dashboard` へ流れる問題
* 必須人数に満たないチームでマッチング開始ボタンが一瞬表示される問題
* 監視の誤検知（Cron 呼び出しの失敗判定を件数から率へ）
* 設計文書と実装の齟齬13件（エラー文言の欠落、Realtime購読の漏れなど）

### Removed

* 単発のレートリセット（`admin-reset-ratings`）。レートの初期化はシーズンリセットへ一本化した（ADR-031）

### Security

* `profiles.avatar_url` の配信元をプロバイダCDNへ限定（Migration 0020）。
  任意のURLを他人の画面の `<img src>` に載せると、閲覧しただけで相手のサーバへIPとUAが渡るため
* 管理者が編集するMarkdownを DOMPurify で無害化（Issue #8）
* `.env` の誤コミットを防ぐ pre-commit フックと gitleaks を追加

# AI運用ルール

AIは以下の場合のみ Changelog の更新を提案する。

* 新しいリリースを作成する場合
* 利用者に影響する変更を実装した場合
* セキュリティ修正を実施した場合

AIはコミット単位ではなく、**リリース単位**で変更履歴をまとめるものとする。
