# Changelog

本プロジェクトの主要な変更履歴を記録する。

この文書は、ユーザーおよび開発者が各バージョンで何が変更されたかを把握するためのものである。

設計判断は **DecisionLog.md**、詳細な変更履歴は **Git履歴** を参照すること。

本書は **Keep a Changelog** の考え方を参考に運用する。

---

# バージョン管理方針

本プロジェクトは Semantic Versioning（SemVer）を採用する。

```
MAJOR.MINOR.PATCH
```

* **MAJOR**：互換性のない変更
* **MINOR**：後方互換性のある機能追加
* **PATCH**：後方互換性のある不具合修正

---

# 更新ルール

以下の場合、本書を更新する。

* 新機能を追加した場合
* 既存機能を変更した場合
* 不具合を修正した場合
* セキュリティ修正を行った場合
* 廃止・削除を行った場合

軽微なリファクタリングやコメント修正など、利用者への影響がない変更は記載しない。

---

# 変更区分

各リリースでは、必要に応じて以下の区分を使用する。

* Added（追加）
* Changed（変更）
* Fixed（修正）
* Deprecated（非推奨）
* Removed（削除）
* Security（セキュリティ）

## [1.0.0] - 2026-08-18

MVPを公開し、公開後の修正と機能追加を反映した最初のタグ付きリリースである。

**★MVPの公開そのものは 2026-08-10 だが、その時点では通しで動かなかった。**
PKCE・CORS・接続方式などクラウド固有の条件で表面化した不具合があり、実利用できる状態に
なったのは 2026-08-16 である。壊れた状態を 1.0.0 として残さないため、**タグは現在の状態へ付けた。**

### Added

**MVP（M1〜M5 / スライス S0〜S6）**

* Discord認証、プロフィール自動作成（`ensure-profile`）
* チーム作成、招待コードによるメンバー招集、脱退、リーダー移譲
* レート差によるマッチング、待機列、`matchmaker` による自動成立
* 勝利申告・承認・拒否、期限切れの自動解決（ADR-014）
* Eloレーティングの更新と `rating_history` への記録
* ランキング（未認証でも閲覧可・ADR-018）、試合一覧・試合詳細
* 管理機能（チームBAN／解除、システム設定、監査ログ・ADR-017）
* Realtime による画面同期、ダークモード

**公開後の追加**

* トップページとルールページ（Issue #8）
* 運営からのお知らせをヘッダーに表示（Issue #7）
* マッチング成立の演出とブラウザ通知（Issue #5）
* 試合確定時のレート変動表示（Issue #6）
* シーズンリセットとシーズン別ランキング（Issue #9 / ADR-030）
* 他チームのメンバー確認（ランキング・試合画面からの導線）
* メンバー一覧へのアイコン表示
* 稼働監視と Discord への通知（ADR-029）
* 選手向け・運営向けマニュアルの同梱
* MITライセンス

### Changed

* チーム人数上限の下限を2から1へ（Issue #4）
* BAN中のチームは編成を変更できないようにした（脱退・リーダー移譲も塞ぐ）
* マニュアルへの導線を設定画面からトップページへ移した
* DB接続を Connection Pooler 経由へ変更（ADR-028）
* CI を PR でのみ実行する運用へ変更し、`main` をブランチ保護した

### Fixed

* Discordログイン後にリダイレクトが解決しない問題（PKCEフロー・BASE_URL）
* すべての更新操作が CORS プリフライトで弾かれる問題
* ログアウト後にヘッダーの表示が切り替わらない問題
* セッション確定前にルータを作り直し、保護ルートが `/dashboard` へ流れる問題
* 必須人数に満たないチームでマッチング開始ボタンが一瞬表示される問題
* 監視の誤検知（Cron 呼び出しの失敗判定を件数から率へ）
* 設計文書と実装の齟齬13件（エラー文言の欠落、Realtime購読の漏れなど）

### Removed

* 単発のレートリセット（`admin-reset-ratings`）。レートの初期化はシーズンリセットへ一本化した（ADR-031）

### Security

* `profiles.avatar_url` の配信元をプロバイダCDNへ限定（Migration 0020）。
  任意のURLを他人の画面の `<img src>` に載せると、閲覧しただけで相手のサーバへIPとUAが渡るため
* 管理者が編集するMarkdownを DOMPurify で無害化（Issue #8）
* `.env` の誤コミットを防ぐ pre-commit フックと gitleaks を追加

### 設計フェーズの決定（MVP確定まで）

以下は公開前の設計フェーズで確定し、MVPに含めて出荷した内容である。
設計判断そのものの正本は `15_DecisionLog.md` である。

#### Added

* 実装ロードマップを縦切りスライス S0 〜 S6 として定義（ADR-023）
* 既知の実装欠陥を Backlog へ B-001 〜 B-012 として登録
* リスク R-011（既存実装と設計書の乖離）を追加
* ReferenceIndex（全文書の索引・正本一覧）を追加
* 試合の自動解決（申告期限切れによる引き分け解散、承認期限切れによる自動承認）を追加（ADR-014）
* 申告内容の拒否（`reject-match`）を追加（ADR-014）
* 監査ログ（`audit_logs`）をMVP対象へ追加（ADR-017）
* ランキングの未認証公開を追加（ADR-018）
* 未定義だった3つのView（team_detail / match_list / match_detail）の定義を追加

#### Changed

* 認証プロバイダを **Discord** に確定し、PoCを不要とした（ADR-022 / R-001 Closed）
* 実装の進行単位を層ごとのPhaseから縦切りスライスへ変更（ADR-023）
* 未適用Migrationに限り直接修正を許可（初版確定までの一度限りの例外。ADR-024）
* APIレスポンス形式とエラーコード体系を `06_ErrorCode.md` へ一本化（ADR-007）
* 試合状態を `PLAYING` / `WINNER_REPORTED` / `COMPLETED` / `DRAWN` に再定義し、`MATCHED` を廃止（ADR-008）
* 勝利申告・承認の実行主体をチームの任意のメンバーへ変更（ADR-009）
* チーム代表者の呼称を `Leader` へ統一（ADR-010）
* チーム参加を招待制のみとしてMVP正式仕様化（ADR-013）
* 認証プロバイダ非依存のプロフィール設計へ変更（ADR-015）
* Edge Functions のトランザクション方式をDB直結へ変更（ADR-016）
* テスト基盤をTypeScriptへ統一し、テストIDへ `TC-` 接頭辞を付与（ADR-012）
* ルーターを TanStack Router に確定し、状態管理に Zustand を明記（ADR-006 / ADR-011）
* ディレクトリ構成を統一し、`supabase/` を正式定義（ADR-019）
* テスト仕様のファイル名をPart番号と内容が分かる形へ改称

#### Fixed

* `matches.completed_at` の定義漏れを修正（ADR-002に準拠）
* 存在しない `teams.status` への参照を全文書から除去
* 「試合開始」APIが未定義のまま前提とされていた矛盾を解消
* RLSポリシーの重複定義による矛盾を解消
* チームリーダーが自チームのレートを直接更新できる権限設計の穴を修正
* 招待コードが全認証ユーザーから参照できる問題を修正
* レート計算の丸めによる総レートの漂流を修正
* ランキングで試合未実施チームが消える／ゼロ除算が起きる問題を修正
* テストIDとエラーコードのID体系の衝突を解消
* 文書優先順位の三重定義を Project Constitution 第9条へ一本化
* 旧文書名・存在しない文書への参照を修正

# AI運用ルール

AIは以下の場合のみ Changelog の更新を提案する。

* 新しいリリースを作成する場合
* 利用者に影響する変更を実装した場合
* セキュリティ修正を実施した場合

AIはコミット単位ではなく、**リリース単位**で変更履歴をまとめるものとする。
