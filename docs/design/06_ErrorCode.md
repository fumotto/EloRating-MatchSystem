# 06_ErrorCode.md

# Error Code Specification

---

# 1. 目的

本書は、本システムで使用するエラーコードを定義する。

エラーコードはフロントエンド、バックエンド、テストコード、ログ解析において共通で使用する。

HTTPステータスコードと組み合わせて利用し、業務エラーとシステムエラーを識別する。

---

# 2. 共通レスポンス形式

## 成功

```json
{
  "result": "OK",
  "data": {}
}
```

## 業務エラー

```json
{
  "result": "NG",
  "error": {
    "code": "TEAM-004",
    "message": "Team is full."
  }
}
```

## システムエラー

```json
{
  "result": "FATAL",
  "error": {
    "code": "SYSTEM-001",
    "message": "Internal server error."
  }
}
```

---

# 3. HTTPステータス方針

| HTTP | 用途       |
| ---- | -------- |
| 200  | 正常終了     |
| 201  | 作成成功     |
| 204  | 削除成功     |
| 400  | 入力値エラー   |
| 401  | 認証エラー    |
| 403  | 権限エラー    |
| 404  | 対象が存在しない |
| 409  | 競合・状態不整合 |
| 422  | 業務ルール違反  |
| 500  | システムエラー  |

---

# 4. エラーコード命名規則

```
<カテゴリ>-<3桁連番>
```

例

```
AUTH-001
TEAM-003
MATCH-002
SYSTEM-001
```

# 14. AI実装ルール

* すべてのAPIは `result` を返却する。
* 成功時は `result = "OK"` を返す。
* 業務エラー時は `result = "NG"` を返す。
* システムエラー時は `result = "FATAL"` を返す。
* エラー時は必ず `error.code` と `error.message` を返却する。
* フロントエンドは `error.code` を基準に画面表示を切り替える。
* テストコードでは HTTPステータスと `error.code` の両方を検証する。
