# Matchmaking Specification

Version 1.0

---

# 1. 目的

本書はチーム同士のマッチング仕様を定義する。

マッチングは固定チーム単位で実施する。

---

# 2. 基本仕様

| 項目      | 値           |
| ------- | ----------- |
| マッチング単位 | チーム         |
| 許容レート差  | 400         |
| マッチング方式 | イベント駆動      |
| 待機方式    | キュー         |
| 同時参加    | 不可          |
| 優先順位    | レート差 → 待機時間 |

---

# 3. マッチング対象

以下の条件をすべて満たすチームを対象とする。

* BANされていない
* マッチ待機中である
* 進行中の試合が存在しない
* チームが有効状態である

---

# 4. マッチング開始

チーム代表者が「マッチング開始」を実行する。

処理

```text
Queue登録

↓

待機開始

↓

Realtime通知
```

待機中は重複してキュー登録できない。

---

# 5. マッチングアルゴリズム

待機キュー登録時にマッチング処理を実行する。

対象チームを検索し、以下の順で優先順位を決定する。

## 第1優先

レート差が最も小さいチーム

---

## 第2優先

待機開始時刻が最も早いチーム

---

## 第3優先

Team ID 昇順

（同一条件時の決定性を保証するため）

---

# 6. レート差判定

レート差は絶対値で判定する。

```text
ABS(TeamA Rating - TeamB Rating)
```

400以下をマッチ対象とする。

---

# 7. マッチ成立

マッチ成立時は以下を実行する。

```text
Match作成

↓

Queue削除

↓

teams.status 更新

↓

Realtime通知
```

生成される Match は

Status

```text
IN_PROGRESS
```

で開始する。

---

# 8. マッチキャンセル

待機中のみキャンセル可能。

キャンセル時

```text
Queue削除

↓

Realtime通知
```

試合開始後はキャンセルできない。

---

# 9. Realtime

通知対象

* Queue登録
* Queue解除
* Match成立
* Match終了

クライアントは通知受信後に必要なデータを再取得する。

---

# 10. エラー

代表的なエラーコード

| Code                  | 内容           |
| --------------------- | ------------ |
| QUEUE_ALREADY_EXISTS  | 既に待機中        |
| TEAM_BANNED           | BAN中         |
| TEAM_ALREADY_IN_MATCH | 試合中          |
| MATCH_NOT_FOUND       | 試合が存在しない     |
| MATCHING_NOT_FOUND    | 条件を満たす相手がいない |

---

# 11. トランザクション

マッチ成立時は以下を単一トランザクションで実施する。

* Queue削除
* Match作成
* チーム状態更新

途中失敗時はロールバックする。

---

# 12. 拡張予定

将来的に以下の機能追加を想定する。

* 待機時間に応じた許容レート差の拡大
* シーズン別マッチング
* ランク帯別マッチング
* 地域別マッチング
* マッチング辞退機能
* AIによるマッチ品質評価

---

# 13. AI実装ルール

* マッチング処理はイベント駆動で実装する。
* キュー登録時にマッチングを試行する。
* レート差を最優先で比較する。
* レート差が同じ場合は待機開始時刻を比較する。
* それでも同一の場合は Team ID 昇順で決定する。
* マッチ成立処理は必ずトランザクションで実行する。
* Realtime通知ではデータ更新を直接行わず、対象データを再取得する。
