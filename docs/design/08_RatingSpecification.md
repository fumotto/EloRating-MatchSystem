# 08_RatingSpecification.md

# Rating Specification

Version 1.0

---

# 1. 目的

本書は本システムで採用する Elo レーティングシステムの仕様を定義する。

レーティングはチーム単位で管理する。

個人レーティングは保持しない。

---

# 2. 基本仕様

| 項目       |          値 |
| -------- | ---------: |
| レーティング方式 | Elo Rating |
| 管理単位     |        チーム |
| 初期レート    |       1500 |
| デフォルトK値  |         32 |
| 引き分け     |    レート変動なし |
| レート保存単位  |         整数 |

---

# 3. レーティング更新タイミング

レート更新は以下の条件を満たした場合のみ実行する。

* 勝者チームが結果を申告済み
* 敗者チームが結果を承認済み
* Match Status が `WINNER_REPORTED` である

更新完了後、Match Status を `COMPLETED` とする。

---

# 4. レーティング計算式

期待勝率（Expected Score）は以下の式で算出する。

```text
Expected = 1 / (1 + 10^((OpponentRating - TeamRating) / 400))
```

---

レート更新式

```text
NewRating = CurrentRating + K × (Actual - Expected)
```

---

Actual

| 結果   |                      値 |
| ---- | ---------------------: |
| 勝利   |                      1 |
| 敗北   |                      0 |
| 引き分け | 0.5（MVPでは変動なしのため計算対象外） |

---

# 5. 引き分け

MVPでは引き分けを採用しない。

引き分けが登録された場合はレートを更新しない。

rating_history は作成しない。

Match Status は `COMPLETED` とする。

---

# 6. 丸め処理

計算結果は小数点以下第一位を四捨五入する。

保存時は整数とする。

例

|   計算結果 |  保存値 |
| -----: | ---: |
| 1512.4 | 1512 |
| 1512.5 | 1513 |
| 1512.9 | 1513 |

---

# 7. K値

デフォルト

32

K値は `system_settings` に保持する。

管理者は変更可能とする。

変更後は次回試合から適用する。

過去試合には影響しない。

---

# 8. 初期レート

新規チーム作成時

```text
1500
```

を設定する。

---

# 9. レート更新処理

更新順序

```text
試合承認

↓

現在レート取得

↓

期待勝率計算

↓

新レート計算

↓

四捨五入

↓

teams 更新

↓

rating_history 登録

↓

matches 完了
```

これらは単一トランザクションで実行する。

---

# 10. rating_history

1試合につき2件登録する。

対象

* Team A
* Team B

保持項目

* 更新前レート
* 更新後レート
* 増減値
* K値
* Match ID
* 更新日時

---

# 11. シーズン

MVPではシーズンを採用しない。

将来的に導入可能な設計とする。

---

# 12. 管理者設定

管理者は以下を変更できる。

* K値

変更は `system_settings` を通じて行う。

---

# 13. AI実装ルール

* レート更新は `approve-match` のみで実行する。
* `report-match` ではレートを更新しない。
* レート更新は必ずトランザクションで実行する。
* 丸め処理は保存直前に一度だけ実施する。
* K値は `system_settings` から取得する。
* 過去の `rating_history` は更新しない。
* レート計算ロジックは共通モジュールとして実装し、複数箇所に重複実装しない。
