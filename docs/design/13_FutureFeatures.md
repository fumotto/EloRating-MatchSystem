# 1. 目的

本書は、MVPでは実装しない機能を整理し、将来の開発計画を管理することを目的とする。

本書は将来機能一覧の正本である。`01_Requirements.md` はMVP対象外の概要のみを記載し、詳細は本書へ集約する。

本書に記載された機能は、要件定義・設計・実装・テストの対象外とする。

## 1.1 MVPで実装済みの機能を記載しない

以下はMVPで実装するため、本書の対象外である。混同しないこと。

| 機能         | MVPでの扱い                              |
| ---------- | ------------------------------------ |
| チーム招待      | MVPの正式仕様（ADR-013）。参加は招待制のみ           |

# 3. High Priority

## 管理者がマッチを用意する（ADR-035 ⑤）

* 管理者による対戦カードの直接作成
* 1チームへの複数試合の同時割り当て
* 大会・イベント運用

自動マッチングを経由しない試合の生成である。前提は `09_MatchmakingSpecification.md` 13.1 に定める。

**★着手前に決めることは無い。ADR-035 が前提を確定済みである。** 同ADRは本機能のために
同時参加の規則を「進行中の試合を持つチームは待機列に登録できない」と定義し直し、
これを偶発的に妨げていた `ux_matches_active_team_a` / `_b` を削除した。

**★着手時に画面を改める必要がある。** 現在 `MatchmakingPage` は進行中の試合を単数として扱っている。

## レート推移の可視化

* レート推移グラフ
* 勝率の推移
* 対戦ごとの変動一覧

`rating_history` テーブル自体はMVPで実装済みである。本項目はその**可視化**を指す。

**★着手前に決めることがある。** `rating_history` はシーズンの削除（`admin-purge-season-data`）で
消える。シーズンを跨いだ推移を見せるなら、削除の対象から外すか、退避先を設けるかを先に決める必要がある。
`season_rankings` に残るのは確定時点の集計のみで、途中経過は含まない。

## 異議申し立て・管理者裁定 — **ADR-033 により不採用**

* ~~確定済み試合への異議申し立て~~
* ~~管理者による結果の訂正~~
* ~~訂正に伴うレートの再計算~~

**採用しない。将来機能としても扱わない。** 検討して採らなかった記録として本項を残す。

一度は ADR-033 の初案として「異議申し立てと管理者裁定」を設計したが、採用しなかった。
本システムは実際のゲームと接続しておらず**勝敗を検証する手段を一切持たない**。検証できない以上、
訂正の可否は管理者の心証に依存し、その心証を支えるのは証拠ではなく当事者の主張である。
訂正機構は精度を上げられないまま、追記訂正・遡及再計算・`VOIDED` の濫用防止といった複雑さだけを持ち込む。

代わりに採ったのは以下である。

| 誤りの種類          | 解決手段                                     |
| -------------- | ---------------------------------------- |
| 勝者申告の押し間違え     | 反対申告（ADR-032 ⑩）。正しい側が申告し直し、誤った側が投了する      |
| 投了の押し間違え       | **覆せない。** 防御は確定前の二段階確認のみ（ADR-032 ①）      |
| 対戦そのものが成立しない   | 不成立の申請（ADR-032 ⑧ ＋ ADR-034 ②）            |
| 虚偽申告の繰り返し      | 通報の累積による BAN（ADR-033 ④⑧）                 |

**確定した結果は覆らない。** 誤った記録が残ることを代償として受け入れている。根拠は
(a) 検証できない以上、訂正の判断も同じ精度でしかできない、(b) レートはシーズンごとに初期化される、
(c) 繰り返す者は BAN で排除され単発の誤りは統計に埋もれる、の3点である（ADR-033 備考）。

**★本項を削除してはならない。** 削除すると、同じ提案が「まだ検討していない機能」として再浮上する。

# 8. AI実装ルール

* 本書に記載された機能はMVPでは実装しない。
* AIは未実装機能を推測して実装してはならない。
* 新機能を実装する場合は、本書および関連設計書を更新してから実装する。
